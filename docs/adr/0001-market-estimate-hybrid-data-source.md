# MarketEstimate は API 優先・Gemini フォールバックのハイブリッドで算出する

Preview に **MarketEstimate**（類似 Product の想定価格帯）を載せる。落札見込みではなく、入札判断のための市場相場である。

データソースは **yahoo_auctions API の落札実績を優先**し、件数不足や識別不能のときだけ **Gemini + Web 検索**に切り替える。API のみだとニッチ Category で「相場なし」が多く、Gemini のみだとヤフオク以外の価格が混ざりやすい。本 Bot のドメインはヤフオクなので、実落札を主軸にしつつカバレッジを Gemini で補う。

## Comparable の条件

- **Category** と **IdentityField**（Category ごとの識別用 Field キー。例: GPU の `model`）が一致する落札取引
- **Condition** は必須にしない（件数確保のため。注記で状態を示す余地は残す）
- **直近 90 日**の落札に限定
- 集計価格は **落札価格のみ**（送料別）。Preview の現在価格と比較軸を揃える
- 価格帯は **25〜75 パーセンタイル**

## フォールバック

| 条件                              | 経路                                         |
| --------------------------------- | -------------------------------------------- |
| IdentityField が得られない        | API を使わず Gemini のみ（注記: 型番未特定） |
| API の Comparable が **5 件未満** | API 結果を捨てて Gemini に切り替え           |
| Gemini も失敗                     | 相場欄を出さない                             |

## 表示

- **Preview 投稿時のみ**（Watch 通知には載せない）
- 形式: 価格帯 + 根拠の一言（例: `¥10,000〜¥15,000（ヤフオク落札 8 件・直近90日）`）
- Extraction 完了後に Preview を先投稿し、MarketEstimate 取得後に **Embed を編集**して相場欄を追記
- 現在価格との「割安/割高」などの自動判定は出さない

## Considered Options

- **API のみ**: データは信頼できるが、ニッチ型番で相場欄が空になりやすい
- **Gemini のみ**: 実装は早いが、ヤフオク以外の相場と混同しやすく Bot の立ち位置からずれる
- **API 件数不足時に API と Gemini を合成**: 価格帯の統合ルールが複雑で初版には過剰
